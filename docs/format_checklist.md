# フォーマットに関するチェックリスト

投稿先のテンプレートや執筆要領に本チェックリストと異なる指定がある場合は，**投稿先の指定を優先する**こと．

各項目の区分は以下の通りである．

- **［必須］** LaTeXとしての誤りを防ぐため，または研究室内で統一するために必ず守る事項
- **［推奨］** 可読性，保守性，査読時の理解しやすさを高める事項
- **［投稿先依存］** 学会・論文誌のスタイルやテンプレートに従う事項

参考資料にした資料：

- [LaTeXにおける正しい論文の書き方](https://qiita.com/birdwatcher/items/5ec42b35d84d3ee2ffbb)

- [イショティハドゥスにキレられないためのLaTeX論文執筆メソッド](https://qiita.com/Ishotihadus/items/bbbb85f54e6a4e7aaac0)

## 1. 基本事項

### 1.1 LaTeXソースの書き方

- [ ] **［必須］** `.tex`ファイルのソースコードでは，一文ごとに改行しているか．
    - 同じ行に複数の文を書かない．
    - 文の途中で改行しない．
    - Gitの差分を文単位で確認しやすくし，一文が長すぎることにも気づきやすくする．
- [ ] **［必須］** 数式環境，`figure`環境，`table`環境，箇条書きなどに適切なインデントを入れているか．
- [ ] **［必須］** 段落を変更するときは，ソースコード上で空行を1行入れているか．
    - 通常は`\par`を直接書くよりも，空行で段落を区切る方が読みやすい．
- [ ] **［必須］** 本文中でレイアウト調整のための強制改行`\\`を使用していないか．
    - 表，数式環境など，構文上必要な場合を除く．
- [ ] **［必須］** `\vspace`，`\hspace`，負の余白などによる場当たり的なレイアウト調整をしていないか．
    - 投稿テンプレートが明示的に許可している場合を除く．
- [ ] **［推奨］** 投稿先テンプレートが指定していないパッケージを不用意に追加していないか．追加する際にはそのパッケージを追加しても問題ないかを調べる．
- [ ] **［推奨］** 同じ記述を何度も使う場合は，意味のあるLaTeXマクロとして定義しているか．
    - ただし，投稿システムとの互換性を損なう複雑なマクロは避ける．

### 1.2 英文中の記号と空白

- [ ] **［必須］** 英文中の半角カンマ`,`，半角ピリオド`.`，コロン`:`，セミコロン`;`の後ろに半角スペースがあるか．
- [ ] **［必須］** 半角開き括弧`(`の前に半角スペースがあるか．また，括弧の内側に不要なスペースがないか．
    - 正：`root mean square error (RMSE)`
    - 誤：`root mean square error(RMSE)`
- [ ] **［必須］** 引用符をLaTeXの規則に従って入力しているか．囲み記号 " " は **`` ''** を使うこと
    - 特に手打ちで参考文献の論文タイトルを打つときに注意すること．ただし，基本的には手打ちで参考文献を書くことはせず，BibTeXを使うこと．
    - (正) $``\text{ ''}$
    - (誤) $\text{" "}$
- [ ] **［必須］** ハイフン，エンダッシュ，エムダッシュを使い分けているか．
    - ハイフン`-`：複合語（例：`deep-learning-based method`）
    - エンダッシュ`--`：範囲や対等な関係（例：`10--20`, `bias--variance`）
    - エムダッシュ`---`：文中の挿入や中断
- [ ] **［推奨］** 単語間の空白を増やす目的で，複数の半角スペースを入力しないこと．

### 1.3 数式モード

- [ ] **［必須］** 本文中の変数や短い数式に，インライン数式モード`$...$`または`\(...\)`を使用しているか．
- [ ] **［必須］** 数式モードの外で変数名を直接書いていないか．
    - 正：`the variable $x$`
    - 誤：`the variable x`

### 1.4 略語・用語

- [ ] **［必須］** 略語は原則として初出時に定義しているか．
    - 正：`support vector machine (SVM)`
    - 誤：`SVM (support vector machine)`
- [ ] **［必須］** 一般名詞を略語の定義時に不要に大文字化していないか．
- [ ] **［推奨］** 一度しか使用しない用語に，不要な略語を導入していないか．
- [ ] **［必須］** 同じ概念に複数の呼称や略語を使用していないか．

### 1.5 単位・化学式

- [ ] **［推奨］** 物理量と単位の表記に`siunitx`パッケージを使用しているか．

```latex
\usepackage{siunitx}

\qty{50}{\micro\meter}
\qty{20}{\degreeCelsius}
```

- [ ] **［投稿先依存］** 古いテンプレートとの互換性が必要な場合は，`\SI`などテンプレートが想定する記法を使用しているか．
- [ ] **［必須］** 数値と単位の間に適切な空白があるか．手作業のスペースではなく，可能な限り`siunitx`に処理させているか．
- [ ] **［推奨］** 化学式や化学反応式に`mhchem`パッケージを使用しているか．

```latex
\usepackage[version=4]{mhchem}

\ce{TiO2}
```

## 2. 相互参照

- [ ] **［必須］** 式番号，図番号，表番号，節番号を本文中に直接入力せず，`\label`と`\ref`，`\eqref`などで参照しているか．

```latex
\begin{equation}
    f(x) = x^2.
    \label{eq:example}
\end{equation}

As shown in \eqref{eq:example}, ...
```

- [ ] **［必須］** `\label`名に一貫した接頭辞を付けているか．
    - 式：`eq:`
    - 図：`fig:`
    - 表：`tab:`
    - 節：`sec:`
    - アルゴリズム：`alg:`
- [ ] **［必須］** `\label`が重複していないか．
- [ ] **［必須］** 図表では，原則として`\caption`の後に`\label`を置いているか．
- [ ] **［必須］** 本文中で図，表，式，節が番号順に参照されているか．`\ref`や`\eqref`を使っている場合は自動で達成される．
- [ ] **［必須］** 本文中で一度も参照されない図，表が残っていないか．
- [ ] **［投稿先依存］** 図・表・式の参照形式が投稿先の規定に従っているか．
    - 文頭ではFig., Tab., Eq.とたった省略表記は使わずにFigure, Table, Equationと省略せず表記することが多い．
    - ただし，IEEEでは図は文頭でも`Fig.~\ref{fig:example}`とする．
    - IEEEでは，表は`Table~\ref{tab:example}`とし，`Tab.`は使用しない．
    - IEEEでは，文中の式は通常`\eqref{eq:example}`のみで参照し，文頭では`Equation~\eqref{eq:example}`とする．
- [ ] **［必須］** `Fig.`，`Table`などと参照番号の間に改行禁止スペース`~`を使用しているか．
    - (例) `Fig.~\ref{fig:name}`, `Table.~\ref{tab:name}`, `Eq.~\eqref{eq:name}`
    - チルダをつけると改行しない半角スペースが入る．
- [ ] **［推奨］** `cleveref`などの相互参照支援パッケージを使用する場合，投稿先の表記規則に合わせて設定しているか．

## 3. 数式

### 3.1 数式環境

- [ ] **［必須］** 数式環境を目的に応じて使い分けているか．
    - `$...$`または`\(...\)`：本文中の数式
    - `\[...\]`：式番号が不要な独立数式
    - `equation`：式番号が必要な単一の数式
    - `align`：等号などをそろえた複数行の数式
    - `multline`：一つの長い数式を複数行に分割する場合
    - `gather`：複数の数式を中央揃えで並べる場合
- [ ] **［必須］** `eqnarray`を使用していないか．
- [ ] **［必須］** 複数行の式に，本文中の強制改行や手作業の空白を使用していないか．
- [ ] **［推奨］** 一つの式番号の下で複数行に分ける場合は，`equation`内で`split`を使用しているか．

```latex
\begin{equation}
    \begin{split}
        \min_{\boldsymbol{x}} \quad & f(\boldsymbol{x}) \\
        \text{subject to} \quad & \boldsymbol{x} \ge 0
    \end{split}
    \label{eq:optimization}
\end{equation}
```

- [ ] **［必須］** 数式も文章の一部として，必要なカンマやピリオドを付けているか．
- [ ] **［推奨］** 数式だけで段落や文を開始せず，導入文を置いているか．

### 3.2 記号の定義と書体

- [ ] **［必須］** 論文中で使用するすべての記号を，初出付近で定義しているか．
- [ ] **［必須］** 同じ記号を異なる意味で使用していないか．
- [ ] **［必須］** スカラー，ベクトル，行列，集合，確率変数の書体を論文内で統一しているか．
- [ ] **［必須］** 本研究室では原則として，ベクトルと行列を太字で表す．
    - 例：`\boldsymbol{x}`，`\boldsymbol{A}`

<!--
- [ ] **［推奨］** ベクトル・行列が多数登場する原稿では，表記の統一と一括変更を容易にするため，意味的なマクロを定義する．pLaTeX，upLaTeX，pdfLaTeXなどの従来型の数式フォント環境では，太字数式記号にbmパッケージの\bmを使用してよい．\bmはラテン文字だけでなく，ギリシャ文字や数学記号にも使用でき，元の記号種別に応じた数式間隔をできるだけ保持できる．

```latex
\usepackage{bm}
\newcommand{\vect}[1]{\bm{#1}}
\newcommand{\mat}[1]{\bm{#1}}
```
-->

- [ ] **［必須］** `\mathbf`と`\boldsymbol`の違いを理解して使用しているか．
    - `\mathbf{x}`は立体の太字英字になる．
    - `\boldsymbol{x}`は元の数式書体を太字化し，ギリシャ文字にも使用できる．
- [ ] **［必須］** 太字，バー，チルダなどの装飾範囲に添字を含めていないか．
    - 正：`\boldsymbol{x}_{i}`
    - 誤：`\boldsymbol{x_i}`
- [ ] **［必須］** 転置と複素共役転置を明確に区別しているか．
    - 転置：`\boldsymbol{A}^{\mathsf{T}}`または`\boldsymbol{A}^{\top}`
    - 複素共役転置：`\boldsymbol{A}^{\mathsf{H}}`
    - 論文内で表記を統一する．

### 3.3 数式中のテキスト・演算子

- [ ] **［必須］** 数式中の単語や略記を，変数の積として誤読されない立体で表しているか．
    - 短い添字：`x_{\mathrm{in}}`
    - 文章：`\text{subject to}`
    - 演算子：`\operatorname{diag}(\boldsymbol{A})`
- [ ] **［必須］** 定義済みの数学演算子をローマン体で記述しているか．
    - `\max`，`\min`，`\log`，`\exp`，`\sin`などを使用する．
    - 正：`\max\{x,0\}`
    - 誤：`max\{x,0\}`
- [ ] **［推奨］** LaTeXの標準にはない演算子をプリアンブルに`\DeclareMathOperator`で定義しているか．
    ```latex
    \DeclareMathOperator*{\argmin}{arg\,min}
    \DeclareMathOperator*{\argmax}{arg\,max}
    \DeclareMathOperator{\tr}{tr}
    \DeclareMathOperator{\rank}{rank}
    \DeclareMathOperator{\diag}{diag}
    ```
    - argminを`\arg \min`と書くのはNG
    - `\DeclareMathOperator`のあとにアスタリスクをつけるのは，下付き文字を演算子の真下に配置できるようにするため．
    - 本文ではargmin_xを`\argmin_{\boldsymbol{x}}`のように書ける．



### 3.4 括弧・縦棒・記号

- [ ] **［必須］** 三点リーダーを文脈に応じて使い分けているか．
    - カンマ区切り：`i=1,2,\ldots,n`
    - 演算子の連続：`1+2+\cdots+n`
- [ ] **［必須］** 集合を定義する縦棒に`\mid`を使用しているか．
    - 正：`\{i \mid i=1,\ldots,n\}`
    - 誤：`\{i | i=1,\ldots,n\}`
- [ ] **［必須］** ノルムを`||...||`で入力せず，`\lVert...\rVert`または`\|...\|`を使用しているか．
    - 推奨：`\lVert \boldsymbol{x} \rVert_2`
- [ ] **［必須］** 内積などの山括弧に`\langle`と`\rangle`を使用しているか．
    - 不等号`<`と`>`で代用しない．
- [ ] **［必須］** `\ll`，`\gg`を不等号の重ね書き`<<`，`>>`で代用していないか．
- [ ] **［必須］** 空集合に`\emptyset`を使用し，`\phi`で代用していないか．
- [ ] **［推奨］** 定義記号には，必要に応じて`mathtools`の`\coloneqq`を使用しているか．
- [ ] **［必須］** 区分的に定義された関数に，原則として`cases`環境を使用しているか．
    - 特殊な配置が必要な場合は`array`等を使用してよい．
- [ ] **［必須］** 行列に適切な環境を使用しているか．
    - 丸括弧：`pmatrix`
    - 角括弧：`bmatrix`
    - 行列式：`vmatrix`
- [ ] **［推奨］** 括弧の大きさが数式内容に対して過大または過小になっていないか．
    - `\left`と`\right`を機械的に使うと括弧が大きくなりすぎる場合がある．
    - 必要に応じて`\bigl`，`\bigr`，`\Bigl`，`\Bigr`などを使用する．
- [ ] **［必須］** 数式の参照に`\eqref`を使用しているか．

## 4. 図

### 4.1 配置とLaTeX記述

- [ ] **［投稿先依存］** 図の配置指定が投稿テンプレートの方針に従っているか．
    - 一般には`\begin{figure}[t]`を使用し，過度に`[H]`で固定しない．
- [ ] **［必須］** 図を本文中で最初に言及した後，できるだけ近くに配置しているか．
- [ ] **［必須］** `figure`環境内で`center`環境を使用せず，`\centering`を使用しているか．
- [ ] **［推奨］** 図の幅を`\linewidth`などの相対値で指定しているか．

```latex
\includegraphics[width=0.8\linewidth]{result.pdf}
```

- [ ] **［必須］** `\linewidth`と`\textwidth`を適切に使い分けているか．
    - 現在の環境で利用できる幅には`\linewidth`を使用する．
    - 2段組をまたぐ`figure*`など，本文全体の幅を明示的に使う場合は`\textwidth`を使用してよい．
- [ ] **［必須］** 図の`\label`を`\caption`の後に置いているか．
- [ ] **［必須］** 図中およびキャプションのパネル記号`(a)`，`(b)`，…が一致しているか．
- [ ] **［投稿先依存］** 複数パネル図に，投稿テンプレートが推奨するパッケージを使用しているか．
    - 一般的なクラスでは`subcaption`を使用できる．
    - IEEEtranでは，原則として`subfig`を`caption=false`付きで使用する．

```latex
\usepackage[caption=false,font=footnotesize]{subfig}
```

- [ ] **［推奨］** LaTeXで適切に配置できない場合は，自分で複数画像を一枚の画像にして保存し，配置することを検討する．
    - 個別参照，再編集，アクセシビリティが低下するが，配置がうまくいかない場合や配置が複雑な場合はこの方法が無難．

### 4.2 可視性と情報量

- [ ] **［必須］** 図のキャプションだけを読んでも，図の目的と主要な内容が理解できるか．
- [ ] **［必須］** 図中の最小文字サイズが，本文または脚注と比べて極端に小さくないか．
    - pythonのmatplotlibで図を作るときには，[科学技術論文に用いる図表のための matplotlib 設定](https://qiita.com/n-taishi/items/042039847601f264236d)が参考になる
    - MATLABで図を作るときには，[MATLABの図を論文に載せるに耐えうる外見にする](https://qiita.com/jirojiro/items/67ffc62a7c5786f52ccb)が参考になる
- [ ] **［必須］** 軸ラベルに物理量名と単位が記載されているか．
- [ ] **［必須］** 凡例，線種，マーカー，色の意味が明確か．
    - 複数の画像にグラフがある場合，各手法の線の色やマーカーは揃えた方が良い．
- [ ] **［必須］** エラーバーや帯が表す統計量を，キャプションまたは本文で説明しているか．
- [ ] **［推奨］** モノクロ印刷や色覚特性の違いがあっても，線種，マーカー，明度差などで識別できるか．
- [ ] **［必須］** 図の周囲に過剰な余白がないか．

### 4.3 画像形式

- [ ] **［必須］** グラフ，チャート，模式図，文字，枠線を含む図をPDF等のベクター形式で保存しているか．
- [ ] **［必須］** ベクター形式の図にフォントが埋め込まれているか．
- [ ] **［投稿先依存］** 写真，自然画像，医用画像などのラスタ画像が，投稿先指定の形式と解像度を満たしているか．
    - PNG，TIFF等の指定に従う．
    - JPEGを使用する場合は，再圧縮を繰り返さない．
- [ ] **［推奨］** PowerPointやIllustratorで数式を含む図を作成する場合，[TeX Clip](https://texclip.marutank.net/)や[LaTeXiT](https://texwiki.texjp.org/?LaTeXiT)等を利用し，数式をベクター形式で挿入しているか．
- [ ] **［必須］** 図中の記号，変数，フォントが本文の数式表記と整合しているか．

## 5. 表

- [ ] **［投稿先依存］** 表のキャプション位置が投稿先の規定に従っているか．
    - 多くの投稿先では表の上に置かれる．指定されたテンプレートを使っていれば問題ない．
- [ ] **［必須］** 表を本文中で最初に言及した後，できるだけ近くに配置しているか．
- [ ] **［必須］** 表の目的と比較条件が理解できるか．
- [ ] **［必須］** 表の単位が列見出しまたはキャプションに明記されているか．
- [ ] **［必須］** 小数点以下の桁数と有効数字が，列内および比較対象間で統一されているか．
- [ ] **［必須］** 最良値を太字，次点を下線などで強調する場合，その意味をキャプションで説明しているか．
- [ ] **［推奨］** 表に不要な縦罫線を使用していないか．
- [ ] **［推奨］** `booktabs`の`\toprule`，`\midrule`，`\bottomrule`を使用しているか．
- [ ] **［必須］** セル内の数値の位置揃えが適切か．

## 6. 参考文献

### 6.1 文献データの管理

- [ ] **［必須］** 投稿先が指定するBibTeX，Biber，手入力形式のいずれかを使用しているか．特に指定がない場合はBibTeXを使う．
- [ ] **［推奨］** Zotero等の文献管理ソフトから`.bib`ファイルを生成し，文献情報を一元管理しているか．
- [ ] **［必須］** BibTeXのエントリ種別が正しいか．
    - 学術雑誌論文：`@article`
    - 国際会議論文：`@inproceedings`
    - 書籍：`@book`
    - 書籍中の章：`@incollection`
- [ ] **［必須］** 著者名，論文タイトル，掲載誌・会議名，出版年，巻，号，ページまたは論文番号が原論文と一致しているか．
- [ ] **［必須］** 同じ文献が異なるBibTeXキーで重複登録されていないか．
- [ ] **［必須］** arXiv版と正式出版版を重複して参考文献に載せていないか．

### 6.2 引用

- [ ] **［必須］** 文献番号や著者年を本文中に直接入力せず，`\cite`等で参照しているか．
- [ ] **［投稿先依存］** 引用番号と句読点の位置が投稿先のスタイルに従っているか．
- [ ] **［推奨］** 引用番号が前の語や文から分離して改行されないよう，テンプレートの推奨方法に従っているか．
    - 必要に応じて`~\cite{smith2020}`を使用する．
    - IEEEtranで`cite`パッケージを使用する場合は，テンプレートの設定に従う．
- [ ] **［必須］** 引用していない文献を参考文献一覧に載せていないか．`BibTeX`を使っている場合，これは自動で防げる．
- [ ] **［必須］** 一つの主張に対して，引用した文献が実際にその主張を支持しているか．
- [ ] **［必須］** 二次文献だけを読んで，未確認の一次文献を直接引用していないか．

### 6.3 表記とスタイル

- [ ] **［必須］** 国際会議名・論文誌名の表記が論文内で統一されているか．
    - 国際会議論文は特に注意する．BibTeX形式で保存するときに表記ゆれしている場合が多い．例えば，ICASSPの論文を引用するときに，`In Proc. ICASSP, 2020` や `in Proc. IEEE Int. Conf. Acoust., Speech Signal Process., 2020` のような表記ゆれはNG．必ず統一すること．
    - IEEE Trans. 系に投稿する場合は，国際会議論文は `in Proc. IEEE Int. Conf. Acoust., Speech Signal Process.` のように`in [各単語を省略表記したProceedings名]`とします．
      - ICASSPは`Proc. IEEE Int. Conf. Acoust., Speech Signal Process.` 
      - NeurIPSは`Proc. Adv. Neural Inf. Process. Syst.`
      - ICMLは`Proc. Int. Conf. Mach. Learn`
      - ICLRは`Proc. Int. Conf. Learn.  Represent.`
      - AISTATSは`Proc. Int. Conf. Artif. Intell. Statist.`
      - CVPRは`Proc. IEEE Conf. Comput. Vis. Pattern Recognit.`
      - ICCVは`Proc. IEEE Int. Conf. Comput. Vis.`
    - 略称が見つからない場合は[List of Title Word Abbreviations](https://marcinwrochna.github.io/abbrevIso/)を使うか，生成AIに聞いて調べる．
    - 投稿する論文誌に規定がない場合は，本研究室では，IEEE Trans.系のルールと同様に`in [各単語を省略表記したProceedings名]`の表記を採用します．
- [ ] **［投稿先依存］** 参考文献のスタイルが投稿先の指定に従っているか．例えば，IEEE Trans.の場合は`IEEEtran.bst`ファイルにより参考文献のスタイルが決まっている．

```latex
\bibliographystyle{IEEEtran}
\bibliography{IEEEabrv,references}
```

- [ ] **［投稿先依存］** IEEEの場合は論文誌・国際会議論文の名前を省略表記にする．
    - Zoteroで`.bib`ファイルを生成するときに`Use Journal Abbreviation`を選択すると論文誌名が省略表記になる．

- [ ] **［投稿先依存］** 雑誌・会議名の略称が必要な場合，投稿先の公式表記または信頼できる略称表を確認したか．
    - 略称が見つからない場合は[List of Title Word Abbreviations](https://marcinwrochna.github.io/abbrevIso/)を使うか，生成AIに聞いて調べる．
- [ ] **［投稿先依存］** 参考文献のタイトルのスタイルを統一する．投稿先のスタイルがTitle Caseまたはsentence caseなのかを確認する．
    - 手作業で機械的に大文字・小文字を変更せず，公式スタイルまたは`.bst`の処理を確認する．
    - 指定がない場合は，本研究室ではsentence caseを採用する．
    -  Title Case: 冠詞や前置詞以外の単語の最初の文字を全て大文字にするフォーマット．(例: AI-Enhanced X-Ray Diffraction Analysis: Towards Real-Time Mineral Phase Identification and Quantification)
    - sentence case: タイトルの先頭語，コロンに続く副題の先頭語，固有名詞，略語・頭文字のみを大文字にするフォーマット．（例: AI-enhanced X-ray diffraction analysis: Towards real-time mineral phase identification and quantification）
    - IEEE系はsentence case．
- [ ] **［必須］** BibTeXタイトル中の略語・固有名詞・大文字を波括弧で保護しているか．BibTeXスタイルによるTitle Case／Sentence case変換を有効にするために必要．今は生成AIにお願いしたら自動でやってくれるはず．

```bibtex
title = {{AI}-enhanced {X-ray} diffraction analysis: {Towards} real-time mineral phase identification and quantification},
```
- [ ] **［必須］** 査読済みの正式出版版が存在する場合，原則としてarXiv版ではなく正式版を引用する．
    - 論文誌や国際会議のproceedingsに載っているのにarXiv論文として引用するのはNG．
    - arXiv版にのみ存在する内容を参照する場合などは，必要に応じてpreprintを引用してよい．
- [ ] **［投稿先依存］** Webページ，ソフトウェア，データセットの引用に，アクセス日，バージョン，URL等が必要か確認したか．

## 7. 日本語原稿

### 7.1 文字種と句読点

- [ ] **［必須］** 数字と欧文に半角文字を使用しているか．
    - 全角数字，全角アルファベットを使用しない．
- [ ] **［投稿先依存］** 句読点として「，．」「、。」のどちらを使用するか，投稿先の規定に従っているか．規定がない場合は，本研究室ではカンマ・ピリオドを採用する．
- [ ] **［必須］** 本文中で句読点の種類が混在していないか．
- [ ] **［投稿先依存］** 日本語中の括弧が投稿先の規定に従っているか．
    - 情報処理学会では，日本語本文の括弧に原則として全角の「（」「）」を使用する．
    - 英文概要，図表見出し，書誌データでは半角括弧を使用する場合がある．
- [ ] **［必須］** 本研究室では，投稿先に規定がない場合，日本語本文の括弧に全角の「（」「）」を使用する．

### 7.2 略語・数字

- [ ] **［必須］** 日本語本文で略語を初出時に定義しているか．
    - 例：有限要素法（Finite Element Method; FEM）
    - 英語名称の大文字・小文字は，固有名詞を除き通常の英文法に従う．
- [ ] **［必須］** 算用数字と漢数字を以下の原則で使い分けているか．
    - 数量，測定値，番号：算用数字
    - 慣用表現や語として定着したもの：漢数字
- [ ] **［必須］** 章，節，項などの番号に算用数字を使用しているか．
    - 例：第1章，第2節，第3項
- [ ] **［必須］** 語として定着した表現に漢数字を使用しているか．
    - 例：二等辺三角形，平均二乗誤差
- [ ] **［必須］** 副詞的な列挙表現を漢数字に統一しているか．
    - 例：「第一に，……．第二に，……．」

### 7.3 表記の統一

- [ ] **［必須］** 同一の語について表記ゆれがないか．
    - 例：「一つ目」「ひとつめ」「一つめ」「1つめ」を混在させない．
- [ ] **［必須］** 投稿先に規定がない場合，本研究室では「一つめ」「二つめ」の表記に統一する．
- [ ] **［必須］** 長音符の有無を論文内で統一しているか．
    - 投稿先の規定，分野の慣習，公的な用語集を優先する．
    - ルールがない場合は，分野の慣習や[JIS規格](http://www.yamanouchi-yri.com/yrihp/techwrt-2-4s/t-2-4s07fa-1.htm)，[内閣府告示](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/naikaku/gairai/honbun06.html)に従うのが良い．ちなみにJIS規格の長音符表は2019年の改正で撤廃されたが，技術文書・IT用語ではこのルールに従っていることが多い．
- [ ] **［投稿先依存］** 常用漢字・送り仮名の使用ルールは投稿する学会のルールに従う
    - 電気情報通信学会: https://www.ieice.org/jpn/shiori/pdf/furoku_d.pdf
    - 基本的に，接続詞には漢字を使わない．
- [ ] **［必須］** 「行う／おこなう」「用いる／もちいる」「できる／出来る」などの表記を論文内で統一しているか．
- [ ] **［推奨］** 話し言葉，曖昧な指示語，主観的な強調表現を避けているか．
